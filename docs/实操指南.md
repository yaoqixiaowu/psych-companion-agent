# 实操指南：API 申请 与 GitHub 提交

本指南覆盖从零开始的两件事：**申请 DeepSeek API Key** 和 **把代码提交到 GitHub**。

---

# 第一部分：申请 DeepSeek API Key

## 1.1 为什么需要它

调用大模型需要一把「钥匙」，即 API Key。它是你的身份凭证：
- 每次调用 API，平台据此识别你并从你的账户余额扣费
- 密钥泄露 = 别人可以用你的钱调用，所以**绝不能提交到 GitHub**

## 1.2 先确认：实验室是否统一提供

作业原文写的是「**大模型 API 由实验室提供**」，因此**优先向实验室索取密钥**，而不是自行注册。

- 向同学或助教确认领取方式，或是否存在公共额度
- 若实验室提供内部端点，把`DEEPSEEK_BASE_URL` 一并改成对应地址
- 实验室没有 → 走下面的自行申请流程

密钥到手后，无论来源是实验室还是自注册，写入 `.env` 的方式完全相同（见1.4）。

## 1.3 自行申请步骤

> 仅在实验室不提供密钥时才需要本节。

### 第1 步：注册账号

访问 https://platform.deepseek.com/

点击右上角「注册」，用手机号或邮箱注册。建议用**手机号**，后续登录更方便。

### 第 2 步：充值

**API 没有赠送额度，需要充值后才能调用。**

参考定价（`deepseek-flash`，官方价，会调整）：

| 项目 | 非高峰期 | 高峰期 |
|---|---|---|
| 输入 / 100万 tokens | $0.15 | $0.30 |
| 输出 / 100 万 tokens | $0.60 | $1.20 |

> 高峰期为北京时间 09:00–12:00、14:00–18:00，其余时段半价（含周末）。

**跑完本作业的全部评测，费用不到 1 美分**（约 15 次调用）。充值 **￥10** 足够完成全部开发与调试。

- 支付宝 / 微信支付均可
- 充值后余额立刻到账

### 第 3 步：创建 API Key

登录后：

1. 点击左侧导航 **「API Keys」**
2. 点击 **「创建 API Key」**
3. 给密钥起个名字，例如 `psych-companion`
4. 点击创建

**关键**：密钥只会完整显示一次！创建后立刻复制保存。

格式类似：`格式为 sk- 开头的一串随机字符`

> 如果不慎关闭页面丢失了，删除旧密钥重新创建一个即可。

**若使用实验室提供的密钥**，跳过本节，直接把对方给的密钥字符串填入 `.env` 即可。注意实验室可能同时提供自定义的 `base_url`，需一并填入。

### 第 4 步：写入项目

在本项目根目录（D:\未来技术习题二）创建 `.env` 文件，内容如下：

```
DEEPSEEK_API_KEY=sk-你刚才复制的那串密钥
```

**Windows 命令行快速创建**：

```bash
copy .env.example .env
```

然后打开 `.env`，把 `sk-在这里填入你的真实密钥` 替换成真实密钥。

> `.env` 已在 `.gitignore` 中，不会被提交。这是它可以安全存放密钥的原因。

### 第 5 步：验证

```bash
pip install -r requirements.txt
python scripts/test_api.py
```

成功输出：

```
[1/3] 正在读取配置...
      Base URL : https://api.deepseek.com
      模型     : deepseek-flash
      密钥     :已配置（前6 位 sk-xxxx）
[2/3] 正在发送测试请求...
      耗时 1.8s
[3/3] [成功]
      模型回复：连接成功
```

### 常见错误对照表

| 报错 | 原因 | 解决 |
|---|---|---|
| `401 Unauthorized` | 密钥错误或过期 | 重新复制 `.env` 中的密钥，注意不要带空格 |
| `402 Insufficient Balance` | 余额不足 | 充值 |
| `429 Rate Limit` | 请求太频繁 | 等待几秒后重试 |
| `ConnectionError` / 超时 | 网络不通 | 检查代理、防火墙 |
| `model not found` | 模型名写错 | 用 `deepseek-flash`，不要用已退役的 `deepseek-v4-flash` |

## 1.6 参考：当前可用模型

| 模型名 | 实际版本 | 上下文 | 说明 |
|---|---|---|---|
| `deepseek-flash` | DeepSeek-V4.1-Flash | 1M | **推荐使用**，性价比高 |
| `deepseek-v4-pro` | DeepSeek-V4-Pro-0813 | 1M | 更强但更贵，一般不需要 |

> 旧模型名 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 已退役，虽仍可调用，但由 V4.1-Flash 服务，**不要在新项目中使用**。

官方文档：https://api-docs.deepseek.com/

# 第二部分：提交到 GitHub

## 2.1 GitHub 账号准备

访问 https://github.com 注册账号（已有则跳过）。

## 2.2 三种认证方式（选一种）

推送到 GitHub 需要身份验证。**推荐方案 2**。

### 方案 1：Personal Access Token（经典）

1. GitHub 右上角头像 → **Settings**
2. 左侧最下方 → **Developer settings**
3. 左侧 → **Personal access tokens** → **Tokens (classic)**
4. 点 **Generate new token (classic)**
5. 填写：
   - Note：随便写，如 `my computer`
   - Expiration：选 30 或 90 天
   - Scopes：**只勾 `repo`** 这一项（勾多了会给不必要权限）
6. 点底部 **Generate token**
7. **立刻复制生成的 token**（形如 `ghp_xxxxxxxxxxxx`），只显示一次

### 方案 2：GitHub CLI（推荐，配置一次永久生效）

```bash
pip install gh
gh auth login
```

按提示选择：
1. `GitHub.com` — 回车确认
2. `HTTPS` — 回车确认
3. 是否用浏览器登录 → 选 `Y`，会打开浏览器让你授权
4. 复制页面显示的一次性验证码，粘贴回终端

完成后终端会显示 `✓ Logged in as 你的用户名`。

### 方案 3：直接在网页上传（最简单，适合第一次）

适合不想碰命令行的情况：

1. 打开你的仓库页面
2. 点击 **Add file** → **Upload files**
3. 把项目文件夹拖进去
4. 底部填 commit 信息，点击 **Commit changes**

局限：只有一次提交记录，不适合展示开发过程。作业要求「开发日志与日常记录」，用命令行分多次提交更合适。

## 2.3 配置 Git 身份

Git 需要知道每次提交是谁做的。**这一步之前是空的，必须配置**：

```bash
git config --global user.name "你的GitHub用户名"
git config --global user.email "你的GitHub邮箱"
```

建议用 GitHub 提供的 noreply 邮箱保护隐私：`用户名@users.noreply.github.com`

验证：

```bash
git config --global user.name
git config --global user.email
```

## 2.4 在 GitHub 上创建空仓库

1. 访问 https://github.com/new
2. **Repository name**：填 `psych-companion-agent`（或你喜欢的名字）
3. **Public/Private**：作业通常选 Public
4.⚠️ **四个勾选项全部不要勾**：
   - ❌ Add a README file
   - ❌ Add .gitignore
   - ❌ Choose a license
   - ❌ Allow "work" to create a branch

   原因：本地已经有这些文件，若GitHub 再创建会导致冲突。
5. 点击 **Create repository**

## 2.5 关联并推送

在项目目录执行：

```bash
# 关联远程仓库，把 your-username 和仓库名换成你自己的
git remote add origin https://github.com/your-username/psych-companion-agent.git

# 推送 main 分支
git push -u origin main
```

推送时如果要求输入凭据：
- Username：你的 GitHub 用户名
- Password：**粘贴第 2.2 节获取的 Token**（不是账号密码！GitHub 已不支持密码认证）

## 2.6 后续日常提交

每次更新代码后：

```bash
git add .
git commit -m "描述这次改了什么"
git push
```

### 提交信息写法

| 不推荐 ❌ | 推荐 ✅ |
|---|---|
| `update` | `feat: 添加危机信号关键词检测` |
| `fix bug` | `fix: 修复医疗边界未清空历史的问题` |
| `改了一下` | `docs: 补充 README 中的评测方法说明` |

前缀含义：`feat` 新功能 / `fix` 修复 / `docs` 文档 / `test` 测试 / `refactor` 重构

### 分阶段提交（推荐，对应「日常记录」要求）

不要一次性把所有代码提交完。按功能分批提交，历史记录本身就是开发日志：

```bash
# 第一次：项目骨架
git add .gitignore .env.example requirements.txt
git commit -m "chore: 初始化项目结构与依赖配置"

# 第二次：核心模块
git add src/persona.py src/safety.py src/strategy.py
git commit -m "feat: 实现角色设定、安全边界与策略选择机制"

# 第三次：评测
git add eval/
git commit -m "feat: 添加评测场景与指标体系"

# 第四次：文档
git add README.md docs/
git commit -m "docs: 补充使用说明与开发日志"
```

这样仓库的历史记录会清晰地展示你的开发过程。

## 2.7 验证是否成功

推送后访问你的仓库页面，应该能看到：

- 所有源码文件
- 提交历史列表（多条记录）
- README.md 在首页渲染出来

# 常见问题

## 提交时提示 `cannot rebase: You have unstaged changes`

**原因**：执行 `git rebase` 前工作区有未提交的改动。rebase 要求工作区干净。

**解决**：先提交或暂存改动，再执行 rebase

```bash
git status                              # 看看哪些文件被改了
git add . && git commit -m "描述这次改动"
git rebase --root --exec 'git commit --amend --reset-author --no-edit'
```

## 推送时提示 `Updates were rejected`

**原因**：远程仓库有你本地没有的提交（例如在网页上创建了 README）。

**解决**：

```bash
git pull origin main --rebase
git push -u origin main
```

## 推送时提示 `remote origin already exists`

**原因**：之前已经关联过远程仓库。

**解决**：先删除再重新关联

```bash
git remote remove origin
git remote add origin https://github.com/你的用户名/仓库名.git
```

## 提示 `fatal: not a git repository`

**原因**：不在项目目录下。

**解决**：先 `cd D:\未来技术习题二`

## 提交时提示 `Please tell me who you are`

**原因**：未配置 Git 身份。

**解决**：执行第 2.3 节的两条配置命令。

## 密钥会不会泄露到 GitHub

**不会**，因为 `.env` 在 `.gitignore` 中。验证方法：

```bash
git status
```

输出中不应出现 `.env` 文件。若出现，说明 `.gitignore` 配置有误，**此时不要提交**，先修正。

也可以在 GitHub 仓库首页搜索 `.env`，确认无此文件。
