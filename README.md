# 知语 · 心理陪伴智能体

面向大学生的心理陪伴对话智能体。基于大模型 API，实现角色设定、安全边界与心理对话策略选择机制。

> **定位声明**：本项目是日常情绪支持与倾听工具，**不是**心理咨询师，**不能**替代专业心理服务。遇到危机情况时，系统会引导用户联系真人专业资源。

---

## 一、快速开始

### 1. 环境要求

- Python 3.10 及以上
- DeepSeek API 密钥（实验室提供或自行申请）

### 2. 安装依赖

```bash
pip install -r requirements.txt
```

### 3. 配置密钥

复制环境变量模板：

```bash
copy .env.example .env        # Windows 命令行
cp .env.example .env          # macOS / Linux
```

打开 `.env`，填入真实密钥：

```
DEEPSEEK_API_KEY=sk-你的真实密钥
```

密钥申请地址：https://platform.deepseek.com/api_keys

> `.env` 文件已被 `.gitignore` 排除，不会提交到 GitHub。请勿将密钥硬编码进源码。

### 4. 验证连通性

```bash
python scripts/test_api.py
```

预期输出：

```
[1/3] 正在读取配置...
      Base URL : https://api.deepseek.com
      模型     : deepseek-flash
      密钥     :已配置（前6 位 sk-xxxx）
[2/3] 正在发送测试请求...
      耗时 1.8s
[3/3] [成功]
      模型回复：连接成功
```

若失败，脚本会按错误类型给出排查建议（401 密钥无效 / 402 余额不足 / 429 请求过频 / 网络不通）。

### 5. 开始对话

```bash
python main.py
```

交互命令：

| 命令 | 作用 |
|---|---|
| `help` | 查看可用命令 |
| `trace` | 查看每轮使用的策略与拦截情况 |
| `reset` | 清空对话状态，重新开始 |
| `quit` | 退出 |

## 三、系统设计

### 3.1 模块结构

```
src/
├── config.py       配置与密钥加载
├── llm_client.py   DeepSeek API 封装
├── persona.py      角色设定与语气（系统 prompt 基底）
├── safety.py       安全边界：危机识别、医疗边界
├── strategy.py     心理对话策略选择机制
└── agent.py        主流程：安全检查 → 策略选择 → 模型调用

eval/
├── scenarios.py    评测场景集
├── metrics.py      评测指标定义
└── run_eval.py     评测执行脚本
```

### 3.2 处理流程

每轮用户输入依次经过三个环节：

```
用户输入
   ↓
[1] 安全边界检查  ← 优先级最高
   │   命中危机 → 立即中断，返回求助渠道（不调用模型）
   │   命中医疗边界 → 拒绝诊断，引导专业机构
   ↓ 通过
[2] 策略选择      ← 规则驱动，可解释可复现
   │   reflect / explore / support / reframe
   ↓
[3] 调用大模型    ← 系统提示词 = 角色基底 + 本轮策略
   ↓
回复用户
```

### 3.3 安全边界设计

明确「不做什么」，比定义「做什么」更重要：

| 边界 | 处理方式 |
|---|---|
| 自伤/自杀信号 | 关键词硬拦截，固定话术引导真实求助渠道，清空历史 |
| 伤人风险 | 同上 |
| 疾病诊断与处方 | 拒绝下结论，但不阻断对话，引导专业机构 |
| 不替用户做决定 | 写入角色提示词，策略层不提供「该选哪个」 |
| 不空洞安慰 | 评测指标自动检测安慰话术 |

危机干预话术依据「陪伴—倾听—鼓励求助」三步原则，提供 24 小时援助热线（12356 全国统一心理援助热线）。

### 3.4 策略选择机制

四种策略源自《心理咨询面谈技术》第 4 版的核心技术：

| 策略 | 适用时机 | 目标 |
|---|---|---|
| 反映与共情 | 首轮、用户情绪强烈 | 让用户感到被理解 |
| 探索与澄清 | 用户描述具体事件 | 把模糊感受说得具体 |
| 支持与鼓励 | 用户提及已做的事 | 强化自我效能 |
| 认知重构 | 已给过建议、用户仍困惑 | 提供新视角，不说教 |

采用**规则驱动**而非模型判定，原因是作业要求评测策略是否有效——规则方案可解释、可复现、可测量。

## 四、评测方法

对应任务目标「让谁去试、试哪些场景、看出什么指标」：

**试什么场景**：5 个场景，覆盖情绪宣泄、表达障碍、决策困惑、安全边界（危机/ 医疗）四类。场景设计针对赛题背景中「学生表达意愿不足」这一特征。

**看出什么指标**（全部可自动计算，不依赖主观打分）：

| 指标 | 含义 |
|---|---|
| 边界正确场景数 | 安全边界是否按预期生效 |
| 空洞安慰率 | 含「一定没事的」等敷衍话术的比例 |
| 越界内容率 | 出现诊断/承诺表述的比例 |
| 平均回复长度 | 是否符合 3–5 句话的语气约束 |
| 提问轮次占比 | 是否在恰当轮次使用开放式提问 |

**谁去试**：当前为自动化评测。后续需引入真实同学试用，收集主观评分（被理解程度、被尊重程度），这部分结果需记录至开发日志。

## 六、已知局限

1. 危机识别基于关键词匹配，会漏检委婉表达（如「活着没意思」）。生产环境应叠加分类模型。
2. 评测目前为自动化指标，缺少真实用户主观评价。
3. 未实现多轮策略切换的自适应学习，策略规则目前为人工设定。
4. 单轮回复长度约束依赖提示词，未做硬性截断。
