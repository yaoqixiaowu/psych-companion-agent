## 试用一：修复前（暴露问题）

- **记录**：`logs/session_20261010_130543.md`
- **轮数**：8 轮，全部正常回复，0 次边界拦截

### 策略分布

| 策略 | 次数 |
|---|---|
| 反映与共情 | 1 |
| 探索与澄清 | 7 |

### 发现的问题

**问题一：策略分布严重失衡**

除首轮外，连续 7 轮全部使用「探索与澄清」（即提问）。第 6–7 轮用户说「怕落后别人」「单纯的怕」时，系统仍在追问：

> 你现在每天大概是怎么过的？

此时本应是共情或认知重构的时机。连续追问会让用户从「被陪伴」变成「被审问」，反而关闭表达。

**根因**：原兜底逻辑为

```python
if turn_index == 0:
    return STRATEGIES["reflect"]
return STRATEGIES["explore"]
```

真实对话中多数轮次都不命中前面的规则，因此全部落入这个兜底分支。规则驱动的设计意图在实践中退化为了固定行为。

**问题二：认知重构策略是死代码**

`select_strategy()` 有 `has_given_advice` 参数，规则 1 靠它触发认知重构。但 `agent.py` 调用时未传该参数：

```python
strategy = select_strategy(user_input, self.turn_index)   # 缺第三个参数
```

永远走默认值 `False`，**「认知重构」在真实对话中一次都不会触发**。只有 `eval/run_eval.py` 单独调用时才生效。

这是**评测与实际行为脱节**——评测显示 5/5 通过，但真实使用时该策略完全不可用。

## 试用二暴露的新问题

虽然策略分布已改善，但发现**策略标签与实际回复内容脱节**：

第 4、6 轮策略标为「支持与鼓励」，回复中却给出了具体建议：

> 你手头有没有老师给的大纲、课件或者往年的题？

而 `support` 策略的提示词明确写了「本轮不要提出新的问题」。

**根因**：模型不总能严格遵守策略提示词。仅靠提示词约束无法保证执行。

**处理**：

1. 重写四个策略的提示词，把禁止项列成清单而非一句话
2. 新增 `check_strategy_consistency()` 自动检测策略与回复是否一致
3. 该指标接入日志统计，退出时可见

用修复前的记录回测，检测准确抓出两处偏差：

```
策略执行偏差:
    第4轮：支持鼓励轮次不应提问，实际回复提出了问题
    第6轮：支持鼓励轮次不应提问，实际回复提出了问题
```

## 试用中发现问题的价值

三个缺陷全部来自真实使用，自动化评测未能覆盖：

| 问题 | 为何评测未发现 |
|---|---|
| 连续 7 轮同策略 | 评测场景轮次少，且未检查连续性 |
| 认知重构成死代码 | 评测直接调用 `select_strategy`，绕过了 `agent.py` |
| 策略与回复脱节 | 评测只检查策略名，不检查回复内容是否匹配 |

这印证了作业要求「让谁去试」的必要性：**自动指标能验证规则是否执行，但验证不了规则在真实场景下是否合理。**
